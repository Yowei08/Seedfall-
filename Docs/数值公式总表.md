# Seedfall 守园者 · 数值计算公式总表

> 生成时间：八期。**已实现的公式**以代码为准（附文件位置）；**设计但未实现**的单独标注。
> 所有"基础值"都是**整数或定值**，"属性"是玩家/植物的成长项——两者相乘得到实算值。

---

## 一、伤害

### 1.1 普通攻击（唯一入口）

```
伤害 = （基础伤害 + 攻击伤害 × 对攻击伤害的继承占比）× 伤害倍率
```

代码：`DamageResolver.AttackFormula(baseValue, atkDamage, inheritMult, atkMult, crit, critDmg, minDamage)`
文件：`Assets/Scripts/Combat/Combat.cs`

- **基础伤害**：每个植物/武器自己的定值
- **继承占比**：每个植物/武器自己的比例（0~1），决定它吃多少玩家的「攻击伤害」
- **伤害倍率**：玩家属性，初始 100%
- **下限保护**：结果不低于 `formula.minDamage`

### 1.2 暴击

```
暴击时：伤害 ×= 暴击伤害
```

| | 初始值 | 说明 |
|---|---|---|
| **玩家暴击率** | **0%** | 完全靠道具堆 |
| **玩家暴击伤害** | **200%**（= 两倍） | 属性面板显示增量（初始 0%） |
| **植物暴击率** | 各自的 `BaseCritRate` | 品种之间可不同 |
| **植物暴击伤害** | 各自的 `BaseCritDmg`（缺省 200%） | |

**植物的实际暴击率 = 自己的基础值 + 玩家暴击率的增量**（两套基准相加，不是取其一）

**⚠️ 陷阱**：玩家暴击率初值为 0，而 `0 × 任何数 = 0`。所以**暴击率道具必须用 `Add` 模式**，
用 `Mul` 会静默失效（买了没反应、日志也不报）。自检里有一条断言专门钉住这个。

### 1.3 爆炸

```
爆炸伤害 = 普通攻击伤害 × 爆炸倍率
```

代码：`DamageResolver.ExplodeFormula(normalDamage, explodeMult)`

**顺序不能反**：先按 1.1 算出普通伤害，**再**乘爆炸倍率。
这样"堆攻击伤害/伤害倍率"对爆炸同样生效，两套成长自动同步。

- **爆炸倍率**：玩家属性，初始 **250%**
- 旧版是一条独立公式 `(爆炸伤害 + 攻击伤害) × 攻击倍率`，只吃攻击伤害一项，
  基础伤害与继承占比都被忽略——已废弃

### 1.4 支援类

```
治疗量 = （基础值 + 攻击伤害 × 继承占比）× 伤害倍率
护卫盾 = （基础值 + 最大生命 × 继承占比）× 伤害倍率      ← 只继承最大生命，不继承护盾
```

## 二、范围

```
攻击范围 = 基础攻击范围（整数）× 攻击范围属性
爆炸范围 = 基础爆炸范围（整数）× 爆炸范围属性
```

- **近战**：影响**判定框大小**（扇形 `arc` 的覆盖）
- **远程**：影响**投掷距离**
- **爆炸**：单独一条，与攻击范围互不影响

缺省规则：`baseExplodeRange ≤ 0` 时按 **3 米**处理（`RunSession.BlastBaseRadius`）。
**准星、前摇标记、真实爆炸三者必须用同一个值**，否则标记会骗人。

## 三、攻速

```
实际攻击间隔（秒）= 植物/武器的 AttackInterval ÷ 攻击速度属性
```

**注意**：面板上植物详情显示的是 `AttackInterval`（2 位小数秒）——那是**未加成的基础间隔**。
玩家属性的攻速加成在运行时另算。

**水壶连续激光**（特例）：
```
扣费间隔 = 0.5 秒 ÷ 攻击速度
同一目标再受伤间隔 = 0.5 秒 ÷ 攻击速度
起手一次、之后每 0.5 秒各扣 10 点充能
```

## 四、经济

### 4.1 商品价格

```
价格 = 道具基础价 × 稀有度倍率 × 波次曲线
波次曲线 = (1 + priceWaveStep) ^ (波次 - 1)        ← 几何增长，非直线
```

`priceWaveStep` 初值 **0.13**（v120 从 0.03 上调，原曲线太缓）。

| 波次 | 倍率 | 萝卜卫士（基础 8） |
|---|---|---|
| 1 | 1.00× | 8 |
| 5 | 1.63× | 13 |
| 10 | 3.00× | 24 |
| 15 | 5.53× | 44 |
| 20 | **10.20×** | **82** |

**目标：第 20 波时萝卜卫士这类低价种子至少 80 金。** 0.03 时只有 1.75× → 14 金，涨了等于没涨。

**为什么用曲线而不是直线**：直线两头都不对——前期价格差不到几个百分点，玩家感觉不到物价在涨；
后期又追不上玩家膨胀的金币收入，商店等于白送。几何曲线**前缓后陡**，压力集中在后段。

**三种商品（种子 / 道具 / 武器）与出售价共用 `ShopPriceFrom`** ——
它们原本各写一份公式，只有道具那份带波次项，于是"道具在涨价而种子和武器永远同价"。

### 4.2 出售价

```
出售价 = 当前波次下该商品的实际价格 × 40%
```

**与定价共用同一个函数**（`RunSession.ShopPriceAt`）。旧版出售价自己写了一份、漏了波次项，
所以"卖价不随波次涨"。

### 4.3 重抽

```
刷新商店  = 基础价 × 2 ^ 已刷新次数
奖励重抽  = 基础价 × 2 ^ 已重抽次数
```

## 五、掉落与恢复

### 5.1 爱心掉落率（等级制）

| 等级 | 名称 | 概率 |
|---|---|---|
| 0 | 低 | 10% |
| 1 | 中 | 15% |
| 2 | 高 | 20% |
| 3 | MAX | 25% |

- **存的是等级（0~3），不是百分比**
- 对应道具：`add: 1` → 升一级；`maxStack: 3` → 升到 MAX 就买不了
- `Stats` 里该属性的上限是 **3**（不是 1）

### 5.2 爱心恢复量

```
恢复量 = 玩家属性 heartHeal（实际值，非增量）
```

## 七、敌人数值成长 【已实现 v115】

```
生命 = 基础血 × (1 + a_hp × (波次−1) + b_hp × (波次−1)²)
伤害 = 基础伤害 × (1 + a_dmg × (波次−1) + b_dmg × (波次−1)²)
BOSS 生命额外 × (1 + bossHpGrowth × (bossIndex − 1))
```

| 系数 | 值 | 作用 |
|---|---|---|
| `hpStepA` | 0.12 | HP 的线性底子 |
| `hpStepB` | 0.006 | HP 的后期加速 |
| `dmgStepA` | 0.08 | 伤害的线性底子 |
| `dmgStepB` | 0.003 | 伤害的后期加速 |

配置位置：`tuning.json` 的 `enemyGrowth` 段。

### 为什么是"线性 + 二次"而不是指数或直线

**直线**：前期没压力，后期被玩家成长甩开。
**指数**（旧实现 `min(2^(波次−1), 64)`）：看着"有成长"，实际 `2^6 = 64`，
**第 7 波就封顶** —— 而一局有 20 波，后 13 波敌人数值完全一样。
**线性 + 二次**：全程连续、无封顶，且每波增幅**本身在变大**。

### 曲线形状（HP，a=0.12 / b=0.006）

| 波次 | 倍率 | 相对上一波 |
|---|---|---|
| 1 | 1.00× | — |
| 5 | 1.58× | +14% |
| 10 | 2.57× | +19% |
| 15 | 3.83× | +24% |
| 20 | **5.45×** | +29% |

### 三条设计要点

1. **HP 涨得比伤害快**（20 波时 HP ×5.45 / 伤害 ×3.32）。
   两者同步的话，后期敌人一击就能秒杀玩家 —— 那是"不讲理"，不是"变难"。
   自检里有一条断言专门守住这个比例。
2. **无封顶**。封顶正是旧实现的问题；自检里那条"持续成长到最后一波"就是防它回归。
3. **Boss 只额外吃 bossIndex 加成**，与普通兵同一条曲线 —— 避免双重压力。

> 注：**刷怪数量**也已是连续成长（v116），见下。

## 七之二、刷怪数量成长 【已实现 v116】

```
额外存活 = floor(maxAliveGrowth × √(波次−1))
额外刷新 = floor(spawnCountGrowth × √(波次−1))
```

系数：`maxAliveGrowth = 9.8`、`spawnCountGrowth = 3.67`（配置在 `tuning.json` 的 `waves` 段）。

### 为什么数量用平方根、而数值用「线性+二次」

**两者的形状刻意相反**：

| | 形状 | 理由 |
|---|---|---|
| **数值**（HP/伤害） | 后期**加速** | 玩家在变强，敌人必须跟上 |
| **数量** | 后期**减速** | 数量加速会撞性能悬崖；而且"人海"比"变硬"更快摧毁手感 |

但**都不封顶** —— 只要还有波次，就还在成长。

旧实现是 `Clamp(系数 × (min(2^(波次−1), 64) − 1), 0, 上限)`：
第 7 波同时撞上指数封顶与数量上限（24 / 9），之后**纹丝不动**。

### 数值对照

| 波次 | HP 倍率 | 伤害倍率 | 额外存活 | 额外刷新 |
|---|---|---|---|---|
| 1 | 1.00 | 1.00 | 0 | 0 |
| 4 | 1.41 | 1.27 | 16 | 6 |
| 7 | 1.94 | 1.59 | **24** | **8** |
| 10 | 2.57 | 1.96 | 29 | 11 |
| 15 | 3.86 | 2.71 | 36 | 13 |
| 20 | 5.45 | 3.60 | 42 | 15 |

**第 7 波那一行与旧实现吻合**（24 / 8）—— 所以前期与中前期的手感不变，
变的只是"第 7 波之后还继续涨"。

## 八、属性叠加规则

```
最终值 =（基础值 + Σ加法修正）× Π乘法修正，再钳到上限
```

- `Add`：直接相加
- `Mul`：相乘（**对 0 无效**）
- 上限见 `Stats.cs` 的 `CapOf`（例如爱心掉落率上限 3 = 等级上限）
