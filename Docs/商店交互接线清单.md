## 3. ★ 唯一的阻塞：一次分层迁移 ★

```
现状：ShopTruck 状态机在  WorldView（表现层）
需要：它在              RunSession（逻辑层）

因为「开店」= SetPhase(PhaseState.Shop, ...) 是【会话状态】✗
而状态机在表现层 ⇒ 两边够不着 ✗
```

### 为什么必须迁，而不是加个桥

**桥（让 WorldView 每帧把"能否交互"写进会话）会造出第二份真相** ✗：

```
ShopTruck.Current == Dock   ← 真值在 WorldView
session.TruckCanShop        ← 影子在 RunSession
```

**这正是本会话反复出现的病根**（三处定价、两个时间源、一个函数两种单位）✗
而它这次的后果会是：**车已经开走了但商店还能开** ✓

### 迁移的做法

```csharp
// ── RunSession ──
public readonly ShopTruck Truck = new ShopTruck();
private bool _truckArmed;

// FixedTick（RunTime += dt; Clock.SyncTo(...) 之后）
if (!_truckArmed && !IsOver) { Truck.Reset(Clock); _truckArmed = true; }
Truck.Tick(Clock);
if (Truck.Current == ShopTruck.Phase.Dock && input.Interact && !IsOver)
    SetPhase(PhaseState.Shop, T.shop.prepareTime);

// 清扫也在这里（世界数据在会话里，不必绕到表现层）
//   Truck.ShouldSweep(isBoss, false) + 距离判定 → World.Enemies.RemoveAt(i)
```

```csharp
// ── WorldView.SyncShopTruck 改为【只读】──
// 只做两件事：取位置、设朝向。不再持有状态机 ✗
var t = session.Truck;                       // 需要 WorldView 拿到 session
bool visible = t.Current != ShopTruck.Phase.Idle;
Vector2 np = ShopTruck.PointAt(t.PhaseT(clock.GameTime));
model.Go.transform.position = new Vector3(np.x * half, 0f, np.y * half);
model.SetFacing(Mathf.Atan2(d.x, d.y) * Mathf.Rad2Deg);
```

### `WorldView` 怎么拿到 session

`SyncShopTruck(World w, float dt)` **只有 World** ✗
`World` 上没有会话引用，也没有 `RunTime`（我这一轮已经撞过一次）✗

**两条路**：
1. 给 `World` 加一个 `RunSession Owner` 反向引用 ✓（简单，但逻辑层反向依赖会话 ✗）
2. **改 `WorldView` 的更新入口签名**，让它拿到 session ✓（干净，但要动调用点）

**建议 2** ✓ —— 调用点只有一处（`WorldView.cs:903` 附近的 `SyncPlayer(w, dt)` 那一族）✓
**而"表现层需要读会话状态"是正常依赖** ✓ 反过来（逻辑层持有表现层对象）才是不正常的 ✓
