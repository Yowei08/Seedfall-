## 1 · 修法（两处，都在副本里）

### 修复 A · 停靠期的车位置（本 bug 本体）

**新增**（`Assets/Scripts/Flow/ShopTruck.cs`）：
```csharp
public Vector2 SamplePoint(Clock clock)
{
    if (Current == Phase.Dock) return DockPoint;   // ★ 只改停靠期 ★
    return PointAt(PhaseT(clock.GameTime));        // 其余三阶段保持原样
}
public float SampleT(Clock clock)
{
    if (Current == Phase.Dock) return 1f;
    return PhaseT(clock.GameTime);
}
```

**四处调用点改为它**：
| 位置 | 作用 | 改前 |
|---|---|---|
| `RunSession.cs` `TickShopTruck` 交互距离 | **玩法** | `PointAt(Truck.PhaseT(...))` |
| `RunSession.cs` `TickShopTruck` 巡回清扫中心 | 玩法（**只在 Looping**） | 同上 |
| `RunSession.cs` `LogShopTruck` 日志 | 诊断 | 同上 |
| `WorldView.cs` `SyncShopTruck` | **表现**（不修就是"界面撒谎"） | 同上 |

★ **为什么这是最小改动** ★：
- **只改 `Dock`** ⇒ 入场/绕场的位移仍由 FBX 动画承担，**演出零变化** ✓
- `Looping`（**唯一会清扫的阶段**）返回值与旧写法**逐位相同** ⇒ **清扫行为不受影响** ✓
- 停靠期停在 `DockPoint` 是唯一的**连续**解：`Path` 最后一点就是 `DockPoint`，
  且 `Looping` 结束时 `PhaseT → 1` ⇒ 车此刻**正好在**停靠位 ✓
  （`SelfCheck:735-736` 独立断言了 `PointAt(1) == DockPoint` ✓ —— 而注释里作者写的
    "最后一点就是停靠位，所以 Looping→Dock 不需要额外求位置" 正是这个意思 ✓
    ⇒ **注释与代码在这里矛盾**，这就是 bug 的证据 ✓）

### 修复 B · 离店时不该把分钟数 +1（修复 A 暴露出来的）

`RunSession.cs` `TickShop` 结尾：
```csharp
// 改前：StartWave(WaveIndex + 1);          // ← 与时钟无关 ✗
// 改后：交给既有的"落后就补"契约
if (Clock.WaveIndex > WaveIndex) StartWave(Clock.WaveIndex);
else SetPhase(PhaseState.Combat, 0f);
```
★ **一处有意的语义变化（必须说明）** ★：
原实现每次离店都白送一次 `StartWave` ⇒ 顺带 `ResetPlayerForNewWave()` **满血 + 满盾** ✗
改后只有"时钟真的跨分钟"时才补 ⇒ **离店不再白送满血** ✓
这与"补满血是每分钟一次的事件"（`StartWave` 的语义）一致 ✓
⇒ ★ 它会让玩家**变弱一点** ✗ 这是 POST2 里几项中位数**下降**的原因之一 ✓
