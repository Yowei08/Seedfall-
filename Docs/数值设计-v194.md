## ⓪ 先说那条连锁：为什么"敌人伤害 ×10"与"玩家血 100/盾 20"能同时成立（以及它的代价）

这一节是本轮最要紧的部分，因为它决定后面所有表怎么读。**它是一道算式题，不是一个取舍题**。

### 三个数

```
玩家血池        maxHp 100 / shield 20        ← 本轮**一个字没动**（用户裁决："玩家生命值100，护盾20"）
敌人伤害 base   grunt.touchDamage 0.7 → 7.0  ← 本轮 ×10（用户："敌人伤害也要10倍"）
换算器          player.hpUnit = 10           ← 本轮**保持 10**（血池没动 ⇒ 换算器也没有改的理由）
```

### 算式链（v193 → v194）

```
v193（改前）
  曲线值 = base 0.7 × 曲线 1.0 × 前段压低 0.65 = 0.455
  血点   = Round(0.455 × hpUnit 10)            = **5**       ⇒ 玩家 100 血 ⇒ 5% 血 ⇒ 20 下致死

v194（本轮）
  曲线值 = base 7.0 × 曲线 1.0 × 前段压低 0.65 = 4.5499997
  血点   = Round(4.5499997 × hpUnit 10)        = **45**      ⇒ 玩家 100 血 ⇒ 45% 血 ⇒ **3 下致死**
```

**这 9 倍的增幅不是笔误，是「×10 乘了两遍」的必然结果** —— 一遍来自表里的 base，
一遍来自专为旧刻度服务的 `hpUnit = 10`。用户裁决明确要求保留它 ⇒ 本轮**按裁决执行**，
没有为了平衡去动血池、动曲线或动 `hpUnit` ✓

### ⚠️ 一处必须纠正的算术（比裁决原文更准）

裁决里推的是"第 1 分钟一下扣 **46** ⇒ 两下死"。**实测是 45，所以是 3 下死**：

```
`7.0f × 0.65f` 在 float 上落在 4.55 的**下方**（4.5499997，不是 4.5500002）
× 10 = 45.499997  ⇒  Mathf.RoundToInt 落到 45（连 .5 都没到，与银行家舍入无关）
⇒ 45 + 45 = 90 < 100 ⇒ **第 3 下才致死**
实测出处：`ProbeV194Num` §②「第 1~10 分钟：基础兵一次触碰 = 玩家血量的百分之几」
```

十进制口算会得到 46，浮点路径给出 45。**以探针读数为准**（这也是"先取证再断言"的用处）✓

### 代价（用户已接受，本轮不修）

详见文末 ⑩「已知后果」。最关键的三条：
① 护盾 20 被一击打穿（退化成"一次性吸收 20 点"）；
② **第 4 分钟起**基础兵一次触碰就 ≥ 100 血点（**一下致死**）；

## ⑥ 伤害取整与弹字取整（三类，探针 §⑥ 读数）

取整的**唯一落点**是 `HealthPool.ApplyDamageSplit`（`Combat.cs`）—— 它是全工程唯一把伤害写进血/盾的地方
（`ApplyDamage` 就是转发到它）。写在这一处，三条路径**一次覆盖**，不可能出现"三份实现、迟早分叉"。

| 类别 | 夹具 | 输入 | 实际扣血 | 结论 |
|---|---|---|---|---|
| ① 玩家→敌人 | grunt（第 20 分钟，血 800） | `RawValue 45.5` | **46** | 带小数的一击被取整 ✓ |
| ② 敌人→玩家 | 玩家 100/20 | 曲线值 `4.5499997` → `PlayerDamagePoints` = **45** | 盾 20 + 血 25 | `Round(4.5499997 × 10) = 45` ✓ |
| ③ DoT（毒） | grunt 第 20 分钟 | `0.15 × 125 = 18.75` | **19** | 毒跳伤被取整 ✓ |
| ③ DoT（火） | 同上（独立夹具） | `0.18 × 125 = 22.5` | **22** | `RoundToInt(22.5)` 是银行家舍入 ⇒ 22 ✓ |
| ③ 小数残量 | 血池 1000 | `ApplyDamage(0.4)` | **1** | `> 0` 的伤害至少 1 点（不会被取整成 0）✓ |

**弹字**（`Actor.Popup`，唯一的上屏入口 —— 敌人受击 / 玩家扣血 / 玩家扣盾 / 三种持续伤害全走它）

```
Text = "-" + max(1, RoundToInt(amount))      ← 一律整数；下限 1 使 "-0" 在数学上不可能出现
```

实测 10 个样本：

```
0.05 → -1      0.4 → -1      0.49 → -1     4.55 → -5      18.75 → -19
45.5 → -46     600.4 → -600  9.5 → -10     2.5 → -2       46 → -46
判据：含小数点 **0 条**｜出现 `-0` 的 **0 条** ✓
```

> `PopupMinAmount = 0.05` 保留：它挡的是 DoT 的 1e-6 级浮点残量。
> 因为下限是 `max(1, …)`，任何能过门槛的数都 ≥ 1 ⇒ 印出来最短是 `-1` ⇒ **永不出现 `-0`** ✓
> 附带调整：`Scale`（大伤害放大）的门槛 8 → **80**，跟着伤害刻度一起 ×10
> —— 不改的话新刻度下**每一次普攻**都会放大，视觉层次会被抹平 ✗

## ⑧ 「爆炸倍率」属性查证（用户："存在异常，没有爆炸倍率这个属性"）

### 8.1 查证结论：**属性存在、道具没配错，缺的是"显示"**

```
StatIds.TryParse("ExplodeDamage") = True｜解析结果 = ExplodeDamage（编号 6）
StatIds.Count = 22｜枚举成员 22                       ← 枚举没有缺项
StatId.BlastDamage  （爆炸伤害，加法点）= 编号 4｜初始 0    ｜上限 9990
StatId.ExplodeDamage（爆炸倍率，**乘数**）= 编号 6｜初始 2.5（250%）｜上限 999
写一次 +1：2.5 → 3.5（250% → 350%）                    ← 属性可读可写 ✓
```

表里引用它的三件道具（`items.json`，`StatIds.TryParse` 全部成功，**没有一条被丢弃**）：

```
blast_grain（爆裂粒）  .effects[0] → ExplodeDamage +1
fertile_core（沃土核） .effects[1] → ExplodeDamage +1
big_bore（大孔径）     .costs[0]   → ExplodeDamage +1（语义 = −1）
```

消费点（**非 UI**，一直是通的）：`RunSession.ExplodeAt` / `Projectile.Explode` /
`SelfCheck` 两条断言 / `ImGuiHud.StatName` 的名字表。肥料那条公式实测：

```
普通一击 (50 + 0) × 1.0 = 50｜× 爆炸倍率 2.5 ⇒ **125**｜倍率 +1（3.5）⇒ **175**（比值 1.4 = 3.5/2.5）✓
```

### 8.2 那"异常"在哪：**v173 把属性面板上那一行删了**

`ImGuiHud` 的属性面板原本有「爆炸倍率」一行，v173 按当时的用户原话
（"属性删除爆炸倍率一栏 ☆ 爆炸伤害计算公式和其它是一样的"）**删掉了那一栏显示**。
于是：道具在卖"爆炸倍率 +1"，玩家在面板上**找不到任何叫「爆炸倍率」的行**
⇒ 只能推断"没有这个属性" ✗ —— **机制没错，显示漏了** ✓

### 8.3 本轮怎么处理

**把那一行加回去**（只改显示，零平衡影响），位置就在「爆炸伤害」下面：

```
爆炸伤害　+0            ← BlastDamage，加法点数（+10），进 (基础 + 属性)
爆炸倍率　+0%           ← ExplodeDamage，乘数（2.5 = 250%），乘在整条算完的伤害上
```

并且把**两者的区别**写进了道具描述，避免下次再被当成同一条：

| | 属性 | 量纲 | 道具给多少 | 效果 |
|---|---|---|---|---|
| 爆炸伤害 | `BlastDamage` | **加法点数** | +10 / +20 / +30 | `(50 + 20) × 1.0 × 2.5 = 175` |
| 爆炸倍率 | `ExplodeDamage` | **乘数** | +1（= +100 个百分点） | `(50 + 0) × 1.0 × 3.5 = 175` |

> ⚠️ 这是一个**回退 v173** 的决定：两次原话指向相反，本轮按**最新一次**执行
> （道具在卖它、玩家要看它）。若要再删，删的就是 `ImGuiHud` 里那一行 `StatLine` ✓

### 发现但**未修**的一个显示缺陷（不在本轮范围）

`Defs.cs` 的 `ItemBonus.Label` 用 `0.#` 格式化，对**小数 Add** 有损：
`CritRate +0.04` 会印成 `+0`、`+0.06` 印成 `+0.1`、`Luck +0.02` 印成 `+0`。
受影响 5 件道具（`lucky_bead` / `gambler_dice` / `barbed_tip` / `heirloom` / `lucky_stone`）。
**它影响的是道具卡上的文字，不影响任何结算**（`StatBlock` 里存的是真值）。
本文档"⑤ 全部道具"表里印的是**真值**（探针直接读 `ItemBonus.Add`，不用 `Label`）✓
